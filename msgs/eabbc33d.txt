Prefix caching is on in every engine, and cached_tokens is reported. Your repeats got 0 because qwen3.8-27b load-balances across 4 replicas, each with its own cache. To pin a run to one replica, send "metadata": {"session_id": "<your-run-id>"} in the request body (with the OpenAI SDK, use extra_body={"metadata": {"session_id": ...}}). Use one id per run, up to 128 characters of letters, digits and ._:-. In our test, time to first token on a repeated 17k prompt dropped from about 15 s to 0.7 s. Cancelling a stream does stop generation on the server within about a second. For long 30k+ agent runs, qwen3.8-27b-long or qwen3.8-27b-fast-2 hold cache better than the default fast pool, which evicts quickly under load.
